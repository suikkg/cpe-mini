# 第 18 课：取消 —— 按下停止之后，那些没跑的单元去哪了

一轮真实测试要跑八到十个小时。跑到第三个小时，操作员发现对端接错了线，
点「停止」。

这一课就问一件事：**报告里那些没跑的单元，长什么样？**

答案不是「没有」。「没有」是这个项目最贵的一种错误。

---

## 1. 先跑

```bash
cargo run -- run fixtures/plan_bidir.json output/cancel.jsonl --cancel-after 1
```

```text
整轮测试在第 1 个单元后被取消。

测试项                        实测速率      门限          结果
──────────────────────────────────────────────────────────────────
TCP 双向 · 第 1 轮 [AB]       954 Mbps      900 Mbps      PASS
TCP 双向 · 第 1 轮 [BA]       944 Mbps      900 Mbps      PASS
UDP 单向 · 第 1 轮            无有效数据    0 Mbps        SKIP
TCP 双向 · 第 2 轮 [AB]       无有效数据    900 Mbps      SKIP
TCP 双向 · 第 2 轮 [BA]       无有效数据    900 Mbps      SKIP
UDP 单向 · 第 2 轮            无有效数据    0 Mbps        SKIP
```

跑完的两条腿有数，剩下四条是 `SKIP`。**六行一行都没少。**

再看退出码：

```bash
echo $?      # 0
```

人按了停止，不是测试失败。写成 1 的话，跑在 CI 里的脚本会以为 CPE 不达标。

## 2. 为什么不能直接 `break`

「停下来」的直觉实现是这样：

```rust
for unit in units {
    if cancel.is_cancelled() {
        break;                    // ← 看起来完全合理
    }
    outcomes.push(execute_unit(unit));
}
```

它是错的，而且错得**很安静**。

`report::rows_from` 是按**腿**摊平成行的（`src/report.rs:66`）：

```rust
for out in outcomes {
    for leg in &out.legs {
        rows.push(Row { ... });
    }
}
```

没有 outcome 就没有行。`break` 之后剩下的四个单元一行都不会有 ——
报告从六行变成两行，**没有任何提示**。

然后第 15 课那个对比就来了：

```bash
cargo run -- compare 上一轮.jsonl 这一轮.jsonl
```

那四行会被判成 `Disappeared`（消失）。而真相是「机器被人按停了」。
看报告的人要么以为计划改过，要么以为程序出了 bug，
**没有人会猜到那是因为有人点了停止**。

> 报告的行数只由计划决定，跟跑没跑完无关。

这条规矩值得记下来。它的一般形式是：**「没发生」和「没记录」必须分得开** ——
和第 04 课那条 `None` ≠ `0.0`、第 16 课那条「没采到丢包」≠「丢包为零」
是同一条规矩的第三次出现。

## 3. 代码

`src/executor.rs`：

```rust
pub fn execute_plan_cancellable(units: &[Unit], cancel: &CancelFlag) -> Vec<UnitOutcome> {
    let mut outcomes = Vec::with_capacity(units.len());
    let mut stopped = false;

    for unit in units {
        if !stopped && cancel.is_cancelled() {
            stopped = true;
        }
        outcomes.push(if stopped {
            cancelled_unit(unit)      // ← 照样产出，只是判定是 SKIP
        } else {
            execute_unit(unit)
        });
    }
    outcomes
}
```

`cancelled_unit` 造出来的单元**照样有腿**，每条腿是：

```rust
verdict: VerdictResult::new(Verdict::Skip, ReasonCode::None, "整轮测试被取消，这个单元没有执行"),
status:  ExecutionStatus::Cancelled,
```

### 判定和执行状态是两件事

`Verdict::Skip` 说的是「这个单元没有结论」。
`ExecutionStatus::Cancelled` 说的是「因为被人按停了」。

两个都要记。只记判定的话，报告里的 `SKIP` 分不出两种来源：

- 计划里本来就要跳过的
- 被取消的

排障时这两种要做的事完全不一样。

> 打开 `src/verdict.rs` 看 `ExecutionStatus` 那个枚举：`CANCELLED` 和
> `TIMEOUT` 一直都在那里，**但在这一课之前，整个项目没有一处产生它们**。
> 枚举里躺着一个没人用的变体，通常说明有一块功能还没做。

### 为什么判定是 `SKIP` 而不是 `SETUP_ERROR`

因为退出码。`run_and_report` 里：

```rust
let bad = t.rate_fail + t.setup_error + t.not_evaluated;
```

`SETUP_ERROR` 会让退出码变成 1。人按了停止，脚本不该以为测试挂了。

## 4. `Arc<AtomicBool>`：为什么不是 `&mut bool`

打开 `src/cancel.rs`。核心就一个字段：

```rust
pub struct CancelFlag {
    flag: Arc<AtomicBool>,
    ...
}
```

因为**置位的人和读取的人不在同一个线程里**：

```text
  Ctrl+C 处理器 ─┐
  Web 界面「停止」─┼─→  AtomicBool  ←─ 执行循环每跑完一个单元读一次
  超时看门狗     ─┘
```

`&mut bool` 同一时刻只能有一个持有者 —— 这个形状根本写不出来。

- `Arc`（原子引用计数）负责「多个地方都持有同一个东西」
- `AtomicBool` 负责「同时读写不算数据竞争」

`clone()` 出来的是**同一个**标志，不是复制一份。`src/cancel.rs` 里有一个
测试专门钉这一点：

```rust
#[test]
fn 别的线程置位主线程看得见() {
    let flag = CancelFlag::new();
    let handle = flag.clone();
    std::thread::spawn(move || handle.request_cancel()).join().unwrap();
    assert!(flag.peek());
}
```

这是整个项目里**唯一一处真的开了线程**的地方。

## 5. 为什么只在单元边界检查

不是省事，是**收尾要跑完**。

真实项目在一个单元结束时要做这些事：停掉对端的 iperf 作业、回收端口、
收日志。这条路径已经被证明能干净地收场。在单元半路上硬停，这些都不会发生 ——
下一次跑就会撞上「端口被占」，而那个错误看起来和取消毫无关系。

> **取消是「跑完手头这个就停」，不是「立刻断电」。**

代价是：点了停止之后最多还要等一个单元（真实项目里可能是十分钟）。
这个代价是故意付的。

## 6. 真实项目里有四个标志，不是一个

打开 `cpe-test` 的 `src/cancel.rs`，开头有四个：

```rust
static RUN_CANCELLED: AtomicBool           // 结束当前这一轮测试
static PROCESS_SHUTDOWN_REQUESTED: AtomicBool  // 退出整个进程（Ctrl+C）
static STOP_REQUESTED: AtomicBool          // 「停掉整轮」的持久意图
static SKIP_CURRENT_UNIT: AtomicBool       // 「跳过这一个」的一次性请求
```

为什么 `RUN_CANCELLED` 和 `STOP_REQUESTED` 要分开？源码里的注释写得很好，
值得原样读一遍：

> 跳过要复用同一套收尾路径（那套路径已经被证明能干净地停掉远端作业、
> 回收端口、收日志），于是它也得设 `RUN_CANCELLED`；而单元边界上要把这个
> 标志清掉才能继续下一个。
>
> 只有一个标志的话，这里有一个**必然出现**的竞态：操作员刚点了「跳过」，
> 紧接着又点「停止」，而单元边界的那次清零会把「停止」一起抹掉——
> 屏幕上写着已请求停止，测试却继续跑完剩下的十个小时。

一个布尔值同时表示两个意思，就会出现「一个动作把另一个动作的意图擦掉」。
这类 bug 复现概率极低（要两次点击卡在同一个单元边界上），
一旦出现就是十小时的代价。

**教学版只留一个标志，是因为它不支持「跳过当前单元」。** 什么时候需要
第二个标志？等你要加「跳过」的时候 —— 见下面的动手任务。

## 7. 那个 `trip_after_polls` 是什么

```rust
pub fn trip_after_polls(n: usize) -> Self
```

这是**教学专用**的扳机：执行循环第 n 次检查时自动置位。
真实项目没有这个东西，那边置位的是 Ctrl+C 处理器和 Web 界面的按钮。

为什么不用 `thread::sleep(3 秒)` 那种更"真实"的演示？因为**跑两次不一样**。
慢机器上会停在不同的单元上，黄金文件对不上，测试时红时绿。

> 演示要可复现，不然教不了东西。
