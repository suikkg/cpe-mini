# 第 03 课：枚举、label 往返与「对外兼容面」

**目标**：理解为什么判定要用 enum，以及为什么它的字符串形式不能随便改。

## 1. 先跑

```bash
cargo run -- demo
cat output/rows.jsonl | head -1
```

注意文件里的判定是 `"PASS"`，不是 `"Pass"`。

## 2. 读代码：`src/verdict.rs`

```rust
pub enum Verdict { Pass, RateFail, Measured, NotEvaluated, SetupError, Skip }

impl Verdict {
    pub fn label(self) -> &'static str { ... }
    pub fn from_label(label: &str) -> Option<Verdict> { ... }
}
```

以及底下的 `mod verdict_serde`：手写 `Serialize` / `Deserialize`，
让 serde 用 `label()` 而不是默认的变体名。

### 两处语法，先认个脸

**`-> &'static str`**

`'static` 是生命周期，念作「活到程序结束」。字符串字面量（`"PASS"` 这种）
就是编译进二进制里的，天然活到最后，所以 `label()` 能放心把它借出去 ——
不用 `String`，就不用分配内存、也不用 clone。

**返回类型写 `&'static str` 而不是 `String`，在这种「一张固定的对照表」上是标准做法。**

**`pub fn label(self)`，不是 `&self`**

第一个参数直接写 `self`，按 rust-starter 第 07 课那张表，
意思是「吃掉自己」—— 但 `Verdict` 上有 `#[derive(Copy)]`，
**Copy 类型「吃掉」就是复制一份**，调用方手里那个原样还在。

```rust
let v = Verdict::Pass;
println!("{}", v.label());
println!("{}", v.label());   // 照样能用，因为 Verdict 是 Copy
```

小的、纯数据的枚举加 `Copy` 之后到处传都不用操心 —— 这是真实项目里
`Verdict` / `ReasonCode` / `ExecutionStatus` 都这么写的原因。

## 3. 为什么不用 serde 默认的 derive

默认 derive 会把 `RateFail` 写成 `"RateFail"`。但报告 HTML、
`task_results.json`、`/api/progress` 里的判定**早就是** `RATE_FAIL` 这种形式了。
rows.jsonl 再引入第二种拼法，等于让同一个概念在同一个产品里有两个名字。

这就是**对外兼容面**：一旦有外部脚本、历史文件、用户认知依赖某个字符串，
它就不再是你随便能改的实现细节了。

## 4. 为什么认不出的串要回落而不是报错

```rust
Ok(Verdict::from_label(&label).unwrap_or_default())
```

新版本可能写出老版本不认识的取值。**宁可把一行显示成「未评估」，
也不要因为一个不认识的枚举值让整份历史报告读不出来。**

`src/reason.rs` 里有同样的处理，测试 `不认识的串回落到None` 钉住了它。

## 5. `from_label` 为什么必须存在

判定在文件里是**字符串**，读回来要变回枚举。如果在读取处再写一份 `match`，
就有了两份映射，改一处漏一处 —— 真实项目的注释管这叫"又一个会漂的口径"。

`tests::每个判定label都能往返` 用一个循环钉住 `label()` 和 `from_label()` 的一一对应。
