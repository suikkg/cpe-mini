# 扩展课 A：把模拟执行换成真的跑一个进程

**先决条件**：12 课全部做完。这一课比前面难，安排两到三天。

**目标**：学会启动外部程序、读输出、解析、处理失败 —— 这是 cpe-test 干的核心事情。

## 1. 为什么拿 ping 练手

前 12 课的样本是写在计划文件里的。真实项目的样本来自 `iperf3`、`ctsTraffic`、
网卡计数器 —— 这些都需要对端机器。`ping` 不需要，本机就能跑，
而且**真实项目里就有 `src/ping.rs`**，做完这一课你可以直接去读它。

先手动跑一次，看清楚要解析什么：

```bash
ping -c 3 127.0.0.1
```

```text
--- 127.0.0.1 ping statistics ---
3 packets transmitted, 3 packets received, 0.0% packet loss
round-trip min/avg/max/stddev = 0.055/0.104/0.164/0.045 ms
```

两行里有四个数要抓：发包数、收包数、丢包率、min/avg/max。

## 2. 启动进程

```rust
use std::process::Command;

let output = Command::new("ping")
    .arg("-c").arg("3")
    .arg("127.0.0.1")
    .output()                      // 跑完再一次性拿输出
    .map_err(|e| format!("ping 起不来：{e}"))?;

let stdout = String::from_utf8_lossy(&output.stdout);
let code = output.status.code();    // Option<i32>
```

三个要点：

**`output()` vs `spawn()`**
`output()` 等它跑完再拿全部输出，适合有限时长的命令。
`spawn()` 边跑边读，真实项目跑 iperf 用的是后者（要实时显示进度）。

**`from_utf8_lossy` 而不是 `from_utf8`**
外部程序的输出不保证是合法 UTF-8（Windows 上尤其）。
`lossy` 把坏字节换成 `�` 而不是报错 —— **不能因为一个乱码字节丢掉整份测量结果**。
真实项目为此专门引了 `encoding_rs`。

**退出码要看，但不能只看**
```bash
ping -c 1 -t 1 192.0.2.1 ; echo $?    # 2（100% 丢包）
ping -c 2 127.0.0.1 ; echo $?          # 0
```
非零退出码说明有问题，但**输出里可能仍然有可用信息**（比如 100% 丢包这个事实
本身就是测量结果）。真实项目的 `execution_error_kind`（`src/ping.rs:275`）
就在区分「工具没起来」和「工具跑了但结果不好」。

## 3. 解析输出

不引 regex（真实项目引了，但这里先用标准库练手）：

```rust
fn parse_loss(text: &str) -> Option<f64> {
    let line = text.lines().find(|l| l.contains("packet loss"))?;
    let field = line.split(',').find(|f| f.contains("packet loss"))?;
    field.trim().split('%').next()?.trim().parse().ok()
}
```

注意每一步都用 `?` 提前退出。解析失败返回 `None`，交给调用方决定怎么办 ——
**解析函数不该自己决定"解析不出来算不算失败"**。
