# 第 01 课：跑通全链路，看懂入口

**目标**：让程序跑起来，并且能说清一条命令是怎么走到业务函数的。

## 1. 先跑

```bash
cd cpe-mini
cargo run -- demo
```

你会看到三种结果：`PASS`、`RATE_FAIL`、`NOT_EVALUATED`。

再试：

```bash
cargo run -- plan fixtures/plan.json      # 只展开，不执行
cargo run -- report output/rows.jsonl     # 读回报告重新渲染
cargo run                                  # 不给命令 → 打印用法
```

## 2. 读代码：`src/main.rs`

只看这个结构：

```rust
fn main() {
    let args: Vec<String> = std::env::args().skip(1).collect();
    std::process::exit(real_main(args));
}

fn real_main(args: Vec<String>) -> i32 {
    let mode = args.first().map(|s| s.as_str()).unwrap_or("");
    match mode {
        "demo" => ...,
        "plan" => ...,
        "run" => ...,
        "report" => ...,
        other => ...,
    }
}
```

三个要点：

1. `args().skip(1)` —— 第 0 个是程序自己的路径
2. `main` 自己不干活，把退出码交给 `real_main`，每个分支明确返回 0 还是 1
3. `match mode` 是整个程序的**分发中心**

## 3. 全链路

```text
plan.json
  → plan::load           读配置 + 校验
  → builder::build_units 展开成测试单元
  → executor::execute_plan  执行
      ├─ rate_window::effective_rx_avg  算有效窗口平均
      └─ verdict::rate_verdict          判定
  → report::rows_from / write_jsonl / render
```

`src/lib.rs` 的 `run_plan()` 就是把这四步串起来，一共 6 行。先看它。

## 4. 动手任务

1. 在 `real_main` 里加一个 `"version"` 分支，打印 `cpe-mini 0.1.0` 并返回 0
2. 在 `help()` 里加上这一行
3. 故意把 `"demo"` 写成 `"demoo"`，跑 `cargo run -- demo`，看会走到哪个分支

## 5. 验收

```bash
cargo run -- version
cargo run -- 乱敲 ; echo "退出码=$?"
cargo test
```

- [ ] `version` 能跑，退出码 0
- [ ] 不认识的命令给提示 + 用法，退出码 1
- [ ] `cargo test` 全绿（56 个测试）
- [ ] 能画出 `cargo run -- demo` 走过的完整调用链
