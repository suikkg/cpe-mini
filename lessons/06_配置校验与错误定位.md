# 第 06 课：配置校验与错误定位

**目标**：让非法配置在开跑前就被拦下，并且报错能让人立刻知道改哪里。

## 1. 先跑

```bash
cargo run -- run fixtures/plan_bad.json
cargo run -- run fixtures/plan_broken.json
```

第一条是**语义**错（JSON 合法但内容不对），第二条是**语法**错。
两种错要给两种提示。

## 2. 读代码：`src/plan.rs::validate`

```rust
pub fn validate(plan: &Plan) -> Result<(), Vec<String>> {
    let mut errors = Vec::new();
    ...
    for (i, spec) in plan.specs.iter().enumerate() {
        let at = format!("specs[{i}]");
        if !matches!(spec.transport.as_str(), "tcp" | "udp") {
            errors.push(format!("{at}.transport 只能是 tcp 或 udp，当前是 {:?}", spec.transport));
        }
        ...
    }
    if errors.is_empty() { Ok(()) } else { Err(errors) }
}
```

三个设计决定：

**返回 `Vec<String>` 而不是第一个错误**

一次报全部。用户改一次就能改完，而不是改一条跑一次、再被下一条拦住。

**报错带位置**

`specs[0].transport` 而不是"配置有误"。用户不该靠猜。

**报错带实际值**

`当前是 "sctp"` —— 用户能立刻看出自己拼错了什么。

## 3. `matches!` 宏

```rust
if !matches!(spec.transport.as_str(), "tcp" | "udp")
```

等价于：

```rust
if !match spec.transport.as_str() {
    "tcp" | "udp" => true,
    _ => false,
}
```

只判断"是不是某几种情况之一"时用它，比写全 `match` 短得多。真实项目用得很多。

## 4. 为什么 `target_mbps == 0.0` 是合法的

`0` 表示"不判定，只记录"，对应 `Verdict::Measured`。只有**负数**才非法。

这类"看起来像错但其实是一种模式"的取值，校验时最容易误杀。
`tests::门限为0是合法的_表示只记录不判定` 钉住了它。

## 5. `#[serde(default)]` 与兼容面

```rust
#[derive(Debug, Clone, Serialize, Deserialize)]
#[serde(default)]
pub struct Plan { ... }
```

缺字段的旧计划文件也能读进来，缺的用 `Default` 补。
没有它，新版加一个字段就会让所有历史计划文件读不出来。

注意 `Plan` 手写了 `Default`（`rounds` 要默认 1 而不是 0），
`Spec` 用 `#[derive(Default)]` 就够了。
