# 第 05 课：所有权在这个项目里长什么样

**目标**：不是重学所有权，而是认出真实代码里的惯用写法。

## 1. 先看三种参数

翻一遍 `src/`，你会看到这三种：

```rust
pub fn effective_rx_avg(samples: &[f64], warmup_secs: usize) -> RateWindow
pub fn execute_unit(unit: &Unit) -> UnitOutcome
pub fn build_units(plan: &Plan) -> Vec<Unit>
```

全是 `&`，一个 `&mut` 都没有。这不是巧合。

## 2. 为什么这一层几乎不用 `&mut`

这些函数都是**输入 → 新数据**，不修改输入：

- `build_units` 拿计划，**造出**新的单元清单
- `execute_unit` 拿单元，**造出**结果
- `rows_from` 拿结果，**造出**报告行

这种写法叫"不可变数据流"。好处很直接：每一步都能单独拿一份输入测试，
不用担心上一步改了什么。`rate_verdict` 更彻底 —— 它是纯函数，
给定输入永远得到同一个输出，所以 `verdict.rs` 里能写 10 个测试而不起任何进程。

## 3. `&[T]` 而不是 `&Vec<T>`

```rust
pub fn effective_rx_avg(samples: &[f64], ...)   // ✅
pub fn effective_rx_avg(samples: &Vec<f64>, ...) // 能用，但不该这么写
```

`&[f64]` 是"一段连续的 f64"，`Vec`、数组、切片都能传进来。
`&Vec<f64>` 只接受 `Vec`。**只读的序列参数一律写 `&[T]`，字符串写 `&str`。**

（这条 rust-starter 第 06 课讲过。这里是它在真实代码里的样子：
整个 `src/` 翻一遍，找不到一个 `&Vec<T>` 参数。）

## 4. 但字段全是 `String`，不是 `&str`

```rust
pub struct Unit {
    pub id: String,        // 不是 &str
    pub title: String,
    ...
}
```

**参数尽量借，字段尽量拥有** —— 这是两条方向相反但都对的惯例。

字段写 `&str` 的话，这个结构体就得带上生命周期：

```rust
pub struct Unit<'a> {      // ← 一旦这样，所有用到 Unit 的地方都要跟着写 <'a>
    pub id: &'a str,
}
```

而且 `Unit` 的寿命从此被拴在计划上：计划一释放，单元就不能用了。
可这个项目里单元要活到报告写完 —— 比计划长。

> **数据要活得比来源久，就让它拥有自己的内容。**
> 多一次 `clone()`，换掉一整条生命周期标注的传染链。这笔账划算得很。

真实项目同理：`src/master/builder.rs` 的 `Unit` 也是全 `String`。

## 5. `clone()` 出现在哪里，为什么

搜一下 `.clone()`：

```bash
grep -rn "clone()" src/
```

集中在两个地方：

1. `builder.rs` 造 `Leg` 时 `spec.samples_ab.clone()` —— 单元要拥有自己的样本，
   因为计划可能先于单元被释放
2. `report.rs` 造 `Row` 时 clone 字符串 —— 报告行要能独立存盘

**这些 clone 是必要的**：新造的数据必须拥有自己的内容。
不必要的 clone 长这样：

```rust
let title = unit.title.clone();
println!("{title}");          // ❌ 只是打印，借用就够了
println!("{}", unit.title);   // ✅
```

## 6. 一个真实的借用冲突

`executor.rs` 里这样写会报错：

```rust
for leg in &unit.legs {              // 只读借用
    unit.legs.push(...);             // 又要可写借用 → 编译错误
}
```

Rust 在编译期拦住了"遍历时修改集合"这类问题。别的语言里这是运行时崩溃或者
静默的数据错乱。
